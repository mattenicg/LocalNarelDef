Quiero que desarrolles un sistema completo de autenticación y administración de productos utilizando **Supabase como backend**, incluyendo Supabase Auth, PostgreSQL y Storage.

No quiero únicamente una interfaz visual: quiero que implementes toda la lógica funcional, conexión con Supabase, base de datos, seguridad y manejo de errores.

## 1. Sistema de registro e inicio de sesión

Crear un sistema de autenticación con:

* Nombre
* Apellido
* Email
* Contraseña

Al registrarse, debe crearse un usuario mediante **Supabase Auth** y además un registro asociado en una tabla `profiles` o equivalente.

Cada usuario debe tener:

* `id` único mediante UUID
* `first_name`
* `last_name`
* `email`
* `role`
* `created_at`

El UUID del usuario debe ser el mismo `auth.users.id` de Supabase.

El rol debe poder ser, como mínimo:

* `user`
* `admin`

Por defecto, todos los usuarios nuevos deben ser `user`.

## 2. Inicio de sesión

Implementar login mediante email y contraseña.

Debe existir:

* Validación de campos
* Mensajes de error claros
* Persistencia segura de sesión
* Logout
* Protección de rutas privadas

Si un usuario ya tiene una sesión activa, no debería poder crear otra sesión simultánea desde otro dispositivo/navegador.

Quiero implementar una política de **una sola sesión activa por usuario**.

Para esto, diseñá una solución segura utilizando Supabase. Si Supabase Auth no permite bloquear directamente múltiples sesiones, implementá un sistema complementario de control de sesiones en PostgreSQL, por ejemplo mediante una tabla `user_sessions` o un mecanismo equivalente.

La solución debe contemplar:

* Identificador único de sesión
* Creación de sesión al iniciar sesión
* Invalidación de la sesión anterior
* Verificación de que la sesión actual siga siendo válida
* Logout
* Expiración de sesión
* Protección contra sesiones inválidas

No guardes contraseñas manualmente en la base de datos. Las contraseñas deben ser manejadas exclusivamente por **Supabase Auth**.

## 3. Restablecimiento de contraseña

Crear una opción:

**"¿Olvidaste tu contraseña?"**

El usuario debe ingresar su email y recibir el email de recuperación mediante Supabase Auth.

Crear también la página para establecer una nueva contraseña.

Debe contemplar:

* Solicitud de recuperación
* Envío del email
* Validación del token
* Nueva contraseña
* Confirmación de contraseña
* Mensajes de éxito/error

## 4. Panel de administración

Crear un panel `/admin` separado del área normal de usuarios.

Solamente los usuarios cuyo `role = 'admin'` en Supabase deben poder acceder.

IMPORTANTE:

La protección del panel **no debe depender únicamente del frontend**.

Implementar las políticas de seguridad correspondientes mediante **Supabase Row Level Security (RLS)** para que un usuario normal no pueda:

* Crear productos
* Modificar productos
* Eliminar productos
* Modificar roles
* Acceder a información administrativa

Aunque intente hacer requests directamente contra Supabase.

## 5. Gestión de administradores

Quiero poder convertir usuarios en administradores directamente desde la base de datos de Supabase.

Si el campo:

`profiles.role = 'admin'`

el usuario tendrá acceso al panel administrativo.

No crear un sistema inseguro donde el frontend pueda modificar su propio rol.

El cambio de `user` a `admin` debe realizarse exclusivamente desde una operación protegida de base de datos/Supabase.

## 6. Gestión de productos

Desde el panel de administración quiero poder:

### Crear productos

Cada producto debe tener:

* `id` UUID único
* `name`
* `description`
* `price`
* `sizes`
* `stock`
* `image_url`
* `created_at`
* `updated_at`

El administrador debe poder ingresar:

* Nombre del producto
* Precio
* Descripción
* Talles disponibles
* Cantidad/stock
* Imagen

### Imagen

Utilizar **Supabase Storage** para almacenar las imágenes.

Crear un bucket específico para los productos.

Cuando el administrador suba una imagen:

1. Validar el archivo.
2. Subirlo a Supabase Storage.
3. Obtener su URL.
4. Guardar la referencia/URL en la tabla `products`.

Permitir formatos de imagen comunes como JPG, JPEG, PNG y WEBP.

Agregar límites razonables de tamaño de archivo.
